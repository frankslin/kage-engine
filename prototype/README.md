# prototype/ — 拼字法造字工具

一個「用簡單拼字法造字」的互動原型：載入 GlyphWiki 上的任何字，點選部件刪除，
搜尋任意部件插入、微調外框，輸出可直接提交 GlyphWiki 的 KAGE 資料字串。

## 使用方式

直接用瀏覽器開啟 `prototype/index.html`（雙擊即可，`file://` 下可運作）。
**需要網路**——字形資料是即時透過 GlyphWiki API（`glyphwiki.org/api/glyph`，
CORS 開放）抓取的，本頁不內嵌任何字形資料。

示範流程（啟動時從 20 個複雜結構字中隨機載入一個當例子；以「槲」為例）：

1. 載入「槲」→ 畫布上點左邊的「木」（紅色高亮，組成列清單同步）。
2. 按「刪除選取的部件」。
3. 在搜尋框輸入「食」→ 列出 GlyphWiki 上實際存在的位置變體
   （`u98df-01` 左偏形、`-02`、`-04`、`-j/-g/-t/-k/-v` 地區形⋯⋯）。
4. 點縮圖插入——外框自動沿用剛刪除部件的位置。
5. 微調位置：選取的列（可多選，含手繪筆畫列）會顯示紅色虛線聯合外框——
   **框內拖曳＝整體移動**；單選一個部件時另有**八個縮放把手**（也支援觸控），
   或用滑桿精確輸入 x1/y1/x2/y2，兩者即時同步重新渲染。
   原地點一下外框可取消選取。
6. 「依位置排序」按鈕把組成列重排成閱讀順序（同一橫排從左到右，否則從上到下）。
   排序依據是**實際渲染的筆墨範圍**而非 99 外框——偏旁形部件（`-01`/`-02` 等）
   的外框常大量重疊，用外框排會錯。
7. 所有修改（刪除/插入/替換/拖曳/縮放/滑桿/排序/重設）都會進歷史棧，
   「復原上一步」按鈕或 ⌘Z／Ctrl+Z 可逐步回退（上限 100 步；
   一段連續滑桿或拖曳只記一筆；載入新字會清空歷史）。
6. 底部輸出框隨時是完整 KAGE 資料，「複製」後可直接貼進 GlyphWiki 的字形編輯框
   （所有部件參照都是 GlyphWiki 上真實存在的部件名）。

## 開發與部署

**開發**：直接雙擊開啟 `prototype/index.html`——它以相對路徑引用上層的
8 個 KAGE 引擎檔（`../2d.js` 等，載入順序不可變，見根目錄
`WALKTHROUGH.md` 第 2 節），引擎改完重新整理頁面即生效，沒有建置步驟。

**部署**：跑 `./build-dist.sh` 組裝 `dist/`——引擎檔複製進 `dist/engine/`、
`index.html` 的引用自動改寫成目錄內路徑（腳本會驗證組裝結果沒有殘留
`../` 引用）。把 **`dist/` 的內容**整個上傳到任何靜態伺服器
（GitHub Pages/Cloudflare Pages/nginx）即可。`dist/` 是建置產物，
已被 `.gitignore` 排除，每次部署前重跑腳本即可，不存在「忘記同步副本」
的問題。

## 實作要點

- **部件選取**：用 `Kage.makeGlyph3()`（逐筆回傳 `Polygons`）搭配
  「每個頂層資料列展開後的筆畫數」把渲染結果分區對應回資料列，
  既保留全字層級的明朝體微調（`adjust*` 系列在完整筆畫集上執行），
  又能知道每個多邊形屬於哪一列、支援點選。
- **別名解參照**：GlyphWiki 上 `uXXXX` 常常只是指向 `uXXXX-j` 等的全框別名
  （單一 `99:` 列、外框 0:0:200:200），載入時自動追到真正有組成列的那層。
- **部品遞迴抓取**：`99:` 參照的部品逐層抓齊後才渲染，記憶體內快取避免重複請求。
- **變體探測**：搜尋部件時自動嘗試 GlyphWiki 的位置變體命名慣例
  （`-01`〜`-14`、`-j/-g/-t/-k/-v/-jv`），只列出實際存在者。

## 部件庫與替換候選（components.js）

`components.js` 由 `build-components.py` 從兩個資料來源離線生成：

1. **GlyphWiki 完整資料傾印**（`dump.tar.gz` 內的 `dump_newest_only.txt`）：
   統計每個字形被 `99:` 參照的次數，收錄 ≥50 次、排除個人空間（名稱含 `_`）的
   3,127 個常用部件，並依 `u+碼位` 命名慣例歸戶到 1,492 個字元
   （`u6728-01` → 木）。
2. **char-components 專案的 `vt.json`**（`../char-components/web/data/vt.json`）：
   853 筆方向安全的單向異體映射（扌→手、氵→水、朩→木⋯⋯），
   把不同寫法的部件連到同一個抽象字元。

這份資料支撐三個功能：

- **插入部件搜尋**：輸入漢字（打字自動搜尋，400ms 防抖）即合併列出
  GlyphWiki 位置變體探測結果與本地常用部件庫的命中項，
  **以渲染結果為指紋簡併同形變體**（如「田」12 個變體只剩 6 種實際不同的形狀），
  按鈕只顯示字形縮圖（名稱在滑鼠提示中）。
- **替換候選**：單選一個部件時，自動列出「同字元的其他位置變體 +
  vt 異體字元的部件」，點縮圖**保留外框原地替換**——例如選中 `u624c-01`（扌）
  會列出 `u624b-01`（手）等候選，這正是「把某部件換成另一種寫法」的一鍵操作。
- **組成列標注**：部件列顯示對應的字元（「部件 木 u6728-01」），不用心算碼位。

重新生成：

```bash
python3 build-components.py <dump_newest_only.txt> [vt.json]
```

## 已知限制（原型階段刻意從簡）

- 非 `99:` 參照的手繪筆畫字，選取粒度是單筆筆畫，還沒有框選/群組。
- 尚未接異體部件候選（`vt.json` 反查之類的 Tier 1 資料來源）。
- 沒有「展開部件」功能（把 `99:` 列攤平成筆畫做更細的編輯）。
- 插入的部件不支援 `99:` 列的伸縮參數（sx/sy），只有外框四值。
