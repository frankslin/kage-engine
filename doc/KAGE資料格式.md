# KAGE / GlyphWiki 字形資料格式規格

本文件說明 GlyphWiki 用來描述漢字字形的 KAGE 資料格式。內容以本 repo 引擎
程式碼（`src/kage.ts`、`src/stroke.ts`、`src/font/*/index.ts`、`src/font/*/cd.ts`）
的實際行為為準；形狀碼的慣用名稱（開放、接續、ハネ⋯⋯）沿用 GlyphWiki 社群用語，
於文中另行標注。

> 本文件初版對照的是上游的純 JS 引擎（`kage.js`/`kagedf.js`/`kagecd.js`）。
> 2026-07-29 引擎改以 `kurgm/kage-engine` 為基礎後，檔案位置已更新如上，
> **資料格式本身沒有變動**（kurgm 與上游輸出相容）。

## 1. 概觀

一個字形（glyph）由一條**資料字串**描述：

```
<列>$<列>$<列>...
```

- 以 `$` 分隔的每一段稱為一**列**（row），代表一筆筆畫或一個部件參照。
- 列內以 `:` 分隔**欄位**，欄位皆為整數（部件參照列的第 8 欄除外，為部件名）。
- 所有座標落在 **200×200 的字身框**內：x 向右增加、y 向下增加，原點在左上。
  座標可以超出 0–200（引擎不裁切），但慣例上筆墨應大致落在框內。
- 列的順序＝繪製順序。多邊形直接疊加，不做布林運算；順序也影響引擎的
  筆畫間自動微調（見第 7 節），慣例按書寫順序（大致左到右、上到下）排列。

範例（「槲」，GlyphWiki `u69f2`）：

```
99:0:0:3:0:150:200:u6728-01$99:0:0:53:0:208:200:u89d2-01$99:0:0:55:0:197:200:u6597-02
```

三列都是部件參照：木（左）、角（中）、斗（右）。

## 2. 列的兩種形態

由第 1 欄（本文稱 `a1`）區分：

| `a1` | 形態 |
|---|---|
| `99` | **部件參照列**：把另一個具名字形縮放平移後嵌入（見第 3 節） |
| 其他 | **筆畫列**：一筆實際繪製的筆畫（見第 4–6 節） |

### 筆畫列的欄位配置

```
a1 : a2 : a3 : x1 : y1 : x2 : y2 [: x3 : y3 [: x4 : y4]]
```

| 欄 | 名稱 | 意義 |
|---|---|---|
| 0 | `a1` | 筆畫類型（第 4 節） |
| 1 | `a2` | 起筆（頭）形狀碼，含高位選項旗標（第 5 節） |
| 2 | `a3` | 收筆（尾）形狀碼，含高位選項旗標（第 5 節） |
| 3–10 | `x1,y1`〜`x4,y4` | 最多 4 組控制點，用到幾組由 `a1` 決定 |

引擎（`getEachStrokes`）一律讀滿 11 欄，缺欄視為 `NaN` 但不影響用不到
該欄的筆畫類型。

## 3. 部件參照列（`a1 = 99`）

```
99 : sx : sy : x1 : y1 : x2 : y2 : 部件名 [: (未用) : sx2 : sy2]
```

| 欄 | 意義 |
|---|---|
| 1, 2 | `sx`, `sy`：伸縮參數（見下） |
| 3–6 | `x1,y1,x2,y2`：目標外框——把部件的 200×200 座標系整體映射到這個矩形 |
| 7 | 被參照的字形名稱（GlyphWiki 上的頁面名） |
| 8 | 未使用（引擎會讀但不參與計算） |
| 9, 10 | `sx2`, `sy2`：兩段伸縮的分界參數（見下） |

### 座標映射

部件內每個座標 `p`（0–200）映射為：

```
x' = x1 + px × (x2 − x1) / 200
y' = y1 + py × (y2 − y1) / 200
```

**允許 `x1 > x2` 或 `y1 > y2`**：映射係數為負，效果是鏡射。
部件參照可以巢狀（部件裡再參照部件），引擎遞迴展開後才繪製，
微調（第 7 節）作用在展開後的全部筆畫上。

### 伸縮（stretch）

`sx`/`sy` 非零時，先對部件座標做**非線性重映射**再套上述外框映射，
用來在壓縮部件時保住筆畫密集區的比例。以 x 方向為例
（y 方向同理，`getEachStrokesOfBuhin`／`stretch()`）：

- 先求部件實際筆墨的 `minX`/`maxX`（控制點範圍，`getBox`）。
- **單段模式**（`sx ≤ 100`）：以 `sx + 100` 為舊分界點、`sx2 = 0`，
  把 `[minX, sx+100]` 線性映射到 `[minX, sx+100 平移後位置]`⋯⋯
  實務上常見寫法是負值，如「槲」左部件 `u6c35-07` 在
  `99:150:0:9:12:73:200:u6c35-07:0:-10:50` 中 `sx=150`（>100，見雙段模式）。
- **雙段模式**（`sx > 100`）：`sx` 減 200 得實際位移量，配合 `sx2`：
  把 `[min, sx2+100]` 映射到 `[min, sx+100−200+100]`、
  `[sx2+100, max]` 映射到 `[sx−100, max]`——即以 `sx2+100` 為折點
  把部件「一邊壓縮、一邊保留」。
- 公式（`stretch(dp, sp, p, min, max)`，`dp`＝位移、`sp`＝折點）：

  ```
  p < sp+100:  p' = floor( (p − min) / (sp+100 − min) × (dp+100 − min) + min )
  p ≥ sp+100:  p' = floor( (p − sp−100) / (max − sp−100) × (max − dp−100) + dp+100 )
  ```

不需要伸縮時 `sx = sy = 0`（最常見），`sx2`/`sy2` 可整欄省略。

## 4. 筆畫類型（`a1`，取 `a1 % 100`）

依 `src/font/mincho/index.ts`、`src/font/gothic/index.ts` 的 `dfDrawFont` 分派（明朝/黑體共通的類型集合）：

| `a1` | 慣用名 | 控制點 | 說明 |
|---|---|---|---|
| 0 | 特殊指示 | `x1,y1,x2,y2` | 不畫筆畫；對「已畫出且完全落在 (x1,y1)-(x2,y2) 框內」的多邊形做翻轉/旋轉（見 4.1） |
| 1 | 直線 | `x1,y1`→`x2,y2` | 兩點直線 |
| 2 | 曲線（單曲線） | `x1,y1`,`x2,y2`,`x3,y3` | 二次貝茲：起點、控制點、終點 |
| 12 | 曲線變種 | 同 2 | 引擎中與 2 同路徑處理（保留碼） |
| 3 | 折れ（轉折） | `x1,y1`,`x2,y2`,`x3,y3` | 直線接直線，折點 `x2,y2` 自動以 `kMage` 半徑倒圓角 |
| 4 | 乙線 | `x1,y1`,`x2,y2`,`x3,y3` | 直線接曲線（「乙」字尾式的 S 形連接），接點自動倒圓 |
| 6 | 複曲線 | `x1..y4` 全用 | 三次貝茲：起點、兩個控制點、終點 |
| 7 | 縦払い | `x1,y1`,`x2,y2`,`x3,y3`,`x4,y4` | 直線段 `x1,y1`→`x2,y2` 接二次曲線 `x2,y2`→(`x3,y3`)→`x4,y4`（豎筆收尾外撇） |
| 9 | 點（停用） | — | 引擎中為 no-op（註解「may not be exist」），不要使用 |

### 4.1 特殊指示列（`a1 = 0`）

由 `a2`/`a3` 選擇操作（`dfTransform`），只影響**在此列之前**畫出、
且**整個落在指定框內**的多邊形：

| `a2` | `a3` | 操作 |
|---|---|---|
| 97 | — | 上下翻轉（y 鏡射） |
| 98 | — | 左右翻轉（x 鏡射） |
| 99 | 1 | 順時針旋轉 90° |
| 99 | 2 | 旋轉 180° |
| 99 | 3 | 旋轉 270° |

另有 `0:0:0:x1:y1:x2:y2` 形式的列在 GlyphWiki 慣例中作為
「字形概念框」的註記（引擎對 `a2=0` 不做任何事）。

## 5. 頭尾形狀碼（`a2`、`a3`）

### 5.1 數字打包

`a2`/`a3` 用**十進位數位打包**多層資訊，引擎以 `% 100`、`% 1000`、
`Math.floor(v/1000)` 等方式拆解：

```
a2 = (萬位選項 × 10000) + (千位選項 × 1000) + 基碼 (0–99)
```

- **基碼**（`% 100`）：形狀本體，見 5.2/5.3。
- **千位/萬位**：程度參數。資料裡手寫的高位很少見；更常見的是
  **引擎的明朝體自動微調（第 7 節）在渲染前把計算出的程度寫進高位**
  （例如 `adjustHane` 對尾碼加 `100×n`、`adjustKakato` 加 `100×n`），
  也就是說高位是「基碼的強度/變體調節旋鈕」，同一套編碼空間
  同時被人工資料與自動微調共用。

### 5.2 頭形狀基碼（`a2 % 100`）

依 `src/font/mincho/cd.ts` 的 `cdDrawCurveU` 中 `switch(a1 % 100)`（對直線另有補充）：

| 基碼 | 慣用名 | 說明 |
|---|---|---|
| 0 | 開放 | 平頭起筆，無裝飾 |
| 1 | — | 與他筆相接的內部接續（不出頭） |
| 2 | 接続（橫） | 接在橫筆上的起筆 |
| 12 | 左上カド | 左上角型起筆（豎筆頂端的方角） |
| 22 | 右上カド | 右上角型起筆 |
| 32 | 接続（縱） | 接在豎筆上的起筆 |
| 6 | — | 曲線用的接續變種 |
| 7 | 細入り／払い入り | 起筆由細漸粗（撇、提的入筆） |
| 27 | 八屋根（俗名） | 7 的變體：同為漸粗入筆但角度處理不同（上游最近一次修正就是此碼的缺點問題） |

### 5.3 尾形狀基碼（`a3 % 100`）

| 基碼 | 慣用名 | 說明 |
|---|---|---|
| 0 | 開放 | 平尾收筆 |
| 1 | — | 內部接續 |
| 2 | 接続（橫）／鱗 | 橫筆收尾；明朝體會在此加上鱗（三角襯線），實際大小受自動微調控制 |
| 32 | 接続（縱） | 接在豎筆上的收尾 |
| 13 | 左下カド | 左下角型收尾 |
| 23 | 右下カド | 右下角型收尾 |
| 24 | 右下カド (T/H) | 23 的台/港設計變體（程式註解「for T/H design」） |
| 313 | 左下 zh 用舊 | 中文舊字形的左下收尾（豎筆微出鋒） |
| 413 | 左下 zh 用新 | 中文新字形的左下收尾 |
| 4 | ハネ（跳ね） | 勾。引擎將其拆解為「主體 + `kMage` 小彎」兩段繪製（`dfDrawFont` 對 `a3%100==4` 的處理），勾的長短由千位高位（自動微調寫入）調節 |
| 5 | （組合用） | 折れ/乙線的特殊收尾組合碼（引擎轉換為 15 等內部碼） |
| 7 | 払い | 出鋒收尾（撇、捺的出尾漸細） |
| 8 | 止め（丸） | 圓頭收尾（引擎對此碼會縮短再畫圓） |
| 14 / 15 | — | 內部轉換碼（引擎把 4/5 依上下文改寫而來，資料中不直接使用） |
| 9 / 17 | — | 引擎中標注「no need」的保留碼 |

**注意**：頭尾碼的合法組合依筆畫類型而異（例如 `4` ハネ只對
直線/曲線/複曲線有意義；`7` 払い用於曲線類）。引擎對不認識的組合
通常靜默畫出開放端，不會報錯——資料寫錯不容易從錯誤訊息發現，
需要目視檢查。

## 6. 座標欄位使用規則彙總

| `a1` | 用到的欄位 | 幾何意義 |
|---|---|---|
| 1 | 3–6 | 起點、終點 |
| 2, 12 | 3–8 | 起點、控制點、終點 |
| 3, 4 | 3–8 | 起點、折點、終點 |
| 6 | 3–10 | 起點、控制點×2、終點 |
| 7 | 3–10 | 直段起點、直段終點（=曲段起點）、曲段控制點、曲段終點 |
| 99 | 3–6（+1,2,9,10） | 目標外框（+伸縮參數） |

`getBox`（部件伸縮所用的筆墨範圍）也按同一規則取欄，
所以**不要在用不到的欄位裡塞非零值**，可能影響部件伸縮計算。

## 7. 引擎的自動微調與格式的關係

明朝體渲染前（黑體不做），引擎會掃描整字的筆畫陣列做七項微調
（`adjustStrokes`）：跳ね長度（`adjustHane`）、彎曲粗細（`adjustMage`）、
豎筆粗細（`adjustTate`）、踵形狀（`adjustKakato`）、鱗大小
（`adjustUroko`/`adjustUroko2`）、切り口（`adjustKirikuchi`，會把頭碼
32 改寫為 132）。這些微調**以在 `a2`/`a3` 高位加數的方式傳遞給繪製層**——
這就是第 5.1 節高位編碼的主要來源。

對格式使用者的實際意義：

1. 同一列資料在不同上下文（周圍筆畫不同）會渲染出略不同的形狀——
   這是特性不是 bug；部件被引用到不同字裡時鱗、勾會自動調整。
2. 手寫高位數值等於覆蓋/疊加自動微調，除非明確知道在做什麼，
   資料中應只寫基碼。

## 8. GlyphWiki 平台慣例（引擎之外、屬於 wiki 的約定）

引擎只認資料字串；以下是 GlyphWiki 網站層面的慣例，投稿時需要遵守：

### 8.1 字形命名

- **已編碼字**：`u` + 小寫十六進位碼位（`u69f2`）。
- **地區字源後綴**（僅用於已編碼字）：`-j`（日本）、`-g`（中國大陸）、
  `-t`（台灣）、`-k`（韓國）、`-v`（越南）、`-h`（香港）；
  無該區字源時的推定設計用 `-jv` 等「virtual」後綴。
- **位置變體**：`-01`（左偏）、`-02`（右旁）、`-03`（冠）、`-04`（脚）
  等到 `-14`，是社群刻意製作的部件形。
- **未編碼字**：以 IDS 命名——IDC 運算子與部件碼位串接，如
  `u2ff0-u98e0-u659b`（⿰飠斛）。**IDS 名不用地區後綴**；同字異設計用
  `-var-001`、異體關係用 `-itaiji-001`（此為對 GlyphWiki 全量資料的
  實測統計結論：77,605 個 IDS 名中 var/itaiji 之外的地區後綴為零）。
- **個人空間**：`使用者名_名稱`，供草稿與私用字形。

### 8.2 別名（alias）

只有單獨一列、外框恰為 `0:0:200:200`、無伸縮的部件參照：

```
99:0:0:0:0:200:200:u69f2-jv
```

慣例上表示「本頁是該字形的別名」。工具處理時應遞迴解參照到
實際有內容的資料（注意迴圈保護）。

### 8.3 「関連字」欄

GlyphWiki 頁面另有一個 related 欄位：已編碼字填對應碼位；
未編碼字填 `U+3013`（〓，測試用佔位記號）。

## 9. 完整範例解讀

「槲」換部件實驗（⿰食斛，`u2ff0-u98e0-u659b-var-001` 候選資料）：

```
99:0:0:0:0:150:200:u98df-01$99:0:0:65:0:217:200:u89d2-01$99:0:0:77:0:200:200:u6597-02
```

| 列 | 解讀 |
|---|---|
| `99:0:0:0:0:150:200:u98df-01` | 部件「食」左偏形，壓進 (0,0)-(150,200)——左半 |
| `99:0:0:65:0:217:200:u89d2-01` | 部件「角」左偏形，外框 (65,0)-(217,200)。注意外框右緣 217 超出 200：`-01` 形的筆墨集中在自己框的左側，框右側是留白，超框是正常手法 |
| `99:0:0:77:0:200:200:u6597-02` | 部件「斗」右旁形，同理筆墨集中在框的右側 |

筆畫列範例（「木」左偏形 `u6728-01` 的四筆）：

```
1:0:0:13:61:90:61        橫（開放/開放）
1:0:0:53:15:53:185       豎（開放/開放）
2:32:7:50:61:40:110:13:148   撇：二次曲線，頭=接続(縱)、尾=払い
2:7:8:55:86:74:94:85:109     點：二次曲線，頭=細入り、尾=丸止め
```

## 10. 給工具作者的注意事項

- 解析時容忍欄位數不足（直線列只有 7 欄是正常的），但輸出時
  建議按第 6 節補齊該類型所需欄位。
- 整數即可；引擎內部以 0.1 精度舍入（`Polygon.push` 的 `floor(x*10)/10`）。
- 別依賴 `a1=9` 或其他保留碼的行為。
- 資料錯誤（未知形狀碼、退化控制點）多半靜默產生怪形而非報錯，
  任何產生器都應以視覺比對驗證輸出。
